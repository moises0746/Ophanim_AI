# Architecture Decision Records

Use an ADR for decisions that are costly to reverse or affect data, security, compatibility, or service boundaries.

File naming:

```text
NNNN-short-decision-title.md
```

Template:

```markdown
# NNNN — Decision title

Status: proposed | accepted | superseded | rejected
Date: YYYY-MM-DD

## Context

What problem and constraints require a decision?

## Decision

What will the project do?

## Consequences

What improves, what becomes harder, and what risks remain?

## Alternatives considered

Which credible alternatives were evaluated and why were they not selected?
```

The README defines direction; ADRs explain durable choices made while implementing that direction.
