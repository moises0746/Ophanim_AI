# Python Standards

## Baseline

Use Python 3.12+. Prefer explicit, readable, typed code. Public and architectural boundaries should avoid `Any`; justify it at dynamic provider edges and immediately normalize the value.

## Types and Models

- Use type annotations for functions, attributes, collections, and async results.
- Use framework-independent dataclasses or small immutable value objects for domain entities where practical.
- Use `StrEnum` or constrained value objects for bounded statuses and classifications; unknown external values must be represented as a safe failure, not silently accepted.
- Use `UUID`/collision-resistant opaque identifiers generated by Core; never derive authority from display names.
- Use timezone-aware UTC `datetime`; convert only at presentation boundaries.
- Use `Decimal` for money, quotas, and other precision-sensitive values.
- Distinguish required values, optional values, and explicit `None`; do not overload empty strings or magic sentinels.
- Prefer immutable tuples/frozen structures for domain values and avoid exposing mutable internal collections.
- Use explicit collection types and bounded sizes at external boundaries.

## Pydantic

Use Pydantic for API request/response DTOs, typed configuration, and validated external adapter schemas. Do not make `BaseModel` the default representation of every domain entity. Map boundary DTOs to domain values explicitly and prevent provider-specific fields from crossing inward.

## Exceptions and Resources

Define stable application/domain error categories and preserve sanitized root causes internally. Do not use exceptions for expected branching when a typed result is clearer. Use context managers/async context managers for clients, sessions, transactions, browser profiles, and resources. Never swallow exceptions or claim success after an unknown outcome.

## Async I/O

Use async I/O for network, provider, database, browser, and event operations where the client is async. Bound every external call with explicit timeouts and cancellation. Do not block the event loop with synchronous network/filesystem work; isolate unavoidable blocking work deliberately.

## Quality

Keep functions cohesive, dependencies injected, and modules small enough for focused tests. Avoid clever metaprogramming, global mutable state, implicit singletons, unbounded recursion, and broad `except Exception` handlers that hide failure.
