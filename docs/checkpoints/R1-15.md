# Task Checkpoint: R1-15 (Transaction Investigation Skill)

**Task ID**: R1-15
**Status**: COMPLETED
**Completed at**: 2026-08-16

**Objective**:
Deliver a Transaction Investigation Skill vertical slice (core skill engine + synthetic
sources) that correlates a validated transaction reference across the reference portal,
the read-only diagnostic ledger (R1-14), structured logs (R1-14), and approved runbook
knowledge, then produces a deterministic classification, findings, and an evidence
audit trail via the assistant event stream. Per the authorized scope decision, the
GUI flow, MCP exposure, and live external portal integration are deferred to later work.

**Architecture impact**:
Adds the first ADR-018 skill to the Core control plane. Skills are typed capabilities
behind `SkillExecutorPort`/`SkillRegistryPort`; the executor performs only read-only
source lookups and deterministic classification, while the registry holds run state.
The domain layer remains framework-free (no FastAPI/SQLAlchemy imports in
`ophanim/domain/`, `ophanim/ports/`, or `ophanim/skills/` — verified by the
architecture guard).

**Security impact**:
- Default-deny: the runtime policy engine combines `diagnostics_policy_rules` +
  `skills_policy_rules`; unapproved skill actions deny at the API boundary (403).
- Read-only by default: the skill issues only parameterized `SELECT` statements against
  the R1-14 read-only tool, searches the JSONL log tool, and queries the in-memory
  portal/knowledge adapters. No write path exists.
- Reference validation at the boundary: malformed reference numbers raise
  `DomainValidationError` (API 422).
- Evidence payloads avoid secret-shaped keys; the R1-14 sanitization rules still apply
  at the tool level.
- No new secrets introduced; credentials stay execution-time resolved.

**Acceptance criteria verification**:
1. Reference intake validates format and returns 422 for malformed input.
2. Approved portal lookup executes and truthfully reports "no portal record found".
3. Read-only ledger lookup via R1-14 returns rows without mutating the ledger
   (`test_ledger_file_is_not_mutated`).
4. Structured log search via R1-14 surfaces matching events and escalates WARNING/ERROR
   levels (`test_warning_log_escalates_to_suspicious`).
5. Runbook knowledge retrieval returns citations only when the caller's workspace
   matches the seeded workspace.
6. Deterministic classification: NORMAL / NEEDS_REVIEW / SUSPICIOUS / HIGH_RISK /
   NO_RECORDS, with the portal-vs-ledger presence gap applied only when the ledger
   source is actually available.
7. Findings and evidence references attach to the run; `evidence.captured` /
   `skill.*` events are broadcast with non-empty `evidence_refs`.
8. Policy denial returns a DENIED run and maps to API 403; unexpected source failure
   returns a FAILED run with `skill.failed` broadcast.
9. Tracker updated; this checkpoint created.

**Migrations/rollback**: N/A — no schema changes. The feature is additive; removing

`runtime.py`/`main.py` wiring rolls back cleanly.

**Known limitations**:
- Reference portal is a synthetic in-memory fixture; the live external portal adapter
  is deferred (per the authorized scope decision).
- No GUI/mobile flow and no MCP exposure yet (deferred to later tasks).
- Classification is deterministic and rule-based; an AI-assist summary layer is a
  future extension point behind the same executor port.
- The presence-gap rule is suppressed when the ledger source is unavailable, so
  degraded-source runs may report fewer indicators (documented truthfully in the run
  limitation).
