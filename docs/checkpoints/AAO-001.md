# AAO-001 Checkpoint — Autonomous Agent Orchestration Foundation

## Task ID

AAO-001 (autonomous agent orchestration foundation; no sprint task ID was
assigned to this request).

## Status

Complete; reviewable implementation. No autonomous merge to `main`.

## Objective

Implement the foundation for an autonomous AI software-engineering workflow:
a user submits a development request and Planner, Developer, QA, and Reviewer
agents collaborate under a deterministic, state-driven Orchestrator until the
task passes defined quality gates and reaches `READY_FOR_MERGE`.

## Scope Delivered

- Explicit validated workflow state machine (`domain/workflow.py`).
- `EngineeringTask` and `Project` aggregates with typed identifiers, branch
  isolation policy, and bounded retry fields.
- Least-privilege agent roles and permission model (`domain/agents.py`).
- Generic provider-agnostic `AgentProvider` port mirroring the conceptual Rust
  trait, plus deterministic `StubAgentProvider`.
- Deterministic quality-gate abstractions (`domain/quality.py`,
  `ports/quality_gate_runner.py`) with `ScriptedGateRunner` and
  `CommandGateRunner`.
- `WorkflowOrchestrator` application service owning all state transitions, the
  bounded QA/retry loop, gate execution, audit events, and persistence.
- In-memory `WorkflowRepository` and `WorkflowEventStore` implementing typed
  ports for projects, tasks, agent runs, gate runs, review results, and
  workflow events.
- Append-only audit events for every material transition.
- `READY_FOR_MERGE` as the final automated state; `COMPLETED` only after an
  explicit human-approved `complete()` call.

## Architecture Impact

Follows the modular-monolith-first baseline. Domain stays framework-independent
(no FastAPI/Pydantic/provider imports; enforced by existing architecture
tests). Application orchestrates through typed ports; adapters and in-memory
persistence implement the ports. PostgreSQL remains the authoritative future
system of record behind the same repository/event-store ports.

## Security Impact

Least-privilege role permissions; QA and Reviewer cannot modify implementation
code. Command execution is constrained to allowlisted argv with bounded
timeouts. Append-only audit events; sanitized prompts and reasons. No
credentials, hidden reasoning, or private source content. No autonomous merge;
`READY_FOR_MERGE` requires human approval. No unrestricted shell or write path
to `main`.

## Migrations/Rollback

No database migration. Persistence is in-memory and intentionally lost on
restart. Rollback is a source revert of the added modules.

## Known Limitations

- Persistence is not durable or multi-process safe.
- No real LLM provider adapter, PostgreSQL implementation, or real Git backend
  yet; `StubAgentProvider`, `ScriptedGateRunner`, and deterministic branch
  naming stand in.
- A provider crash aborts the current step and raises `AgentExecutionError`
  (recorded as an `AGENT_FAILED` event); the task remains in a valid state for
  human intervention.
- No HTTP API routes yet.
- Only the five initial roles are implemented.

## Open Risks/Blockers

Real provider, PostgreSQL, and Git integrations require later explicit
authorization. Gate command defaults (`ruff`, `pytest`, `compileall`) are
Python-oriented; project-specific gate configuration is a future task.
