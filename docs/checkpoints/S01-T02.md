## Implemented Domain Types

- `TaskId`, `TaskStepId`, and `CorrelationId`: immutable UUID-backed opaque identifiers with parsing and Core-side generation helpers.
- `TaskStatus` and `TaskStepStatus`: bounded conceptual lifecycle values from the accepted lifecycle contract.
- `Environment`, `RiskLevel`, and `PrivacyMode`: bounded domain classifications.
- `DataScope`: immutable workspace/source/classification scope value with bounded non-empty fields.
- `Task`: immutable aggregate with owner, objective, scope, risk/privacy/environment, correlation, status, priority, timestamps, and owned steps.
- `TaskStep`: immutable bounded work unit with owning task, objective, status, sequence, dependencies, and timestamps.
- `DomainValidationError`: minimal framework-independent validation error.

## Invariants

- Identifiers must be valid UUID values.
- Domain text fields are non-empty and bounded.
- Domain timestamps must be timezone-aware and normalized to UTC; `updated_at` cannot precede `created_at`.
- Priorities and step sequences are non-negative.
- Task steps must reference their owning Task and have unique IDs within that aggregate.
- Task steps cannot depend on themselves and dependency IDs must be `TaskStepId` values.
- Domain code imports only standard-library modules and the domain error module; no framework/provider/runtime dependency was introduced.
