**Objective**:
Deliver Observability & Packaging for Ophanim Core: OpenTelemetry-ready instrumentation
(optional, off by default), truthful health probes (`/health` + `/readyz`), structured
JSONL logging with secret redaction, dependency-free Prometheus-style metrics
(`/metrics`), and Docker compose + local build configs for the core service and a local
telemetry stack.

**Scope delivered**:
- `ophanim/config.py` — new settings: `service_name`, `log_level`, `log_path`,
  `metrics_enabled`, `otel_enabled`, `otel_otlp_endpoint`, `readyz_timeout_seconds`,
  `readyz_required_components` (+ `readyz_required_components_list` property).
- NEW `ophanim/observability/` package:
  - `logging.py` — `JsonlFormatter` (stable schema, redacts extras), `SecretRedactionFilter`

    (stderr + optional rotating file handler), `get/set_correlation_id` context vars.
  - `metrics.py` — thread-safe `MetricsRegistry` with counters/histograms and a
    dependency-free Prometheus text renderer; `record_request`, `record_policy_decision`,
    `record_tool_call`, `record_skill_run` helpers.
  - `middleware.py` — `ObservabilityMiddleware`: honors/echoes `X-Correlation-ID`
    (validates UUID, generates otherwise), records request metrics, emits structured
    access logs to `ophanim.access`, wraps requests in an optional OTel span, restores
    prior correlation context.
  - `otel.py` — lazy, optional OpenTelemetry bridge (`init_otel`/`shutdown_otel`/
    `maybe_start_span`); every entry point degrades to a no-op when disabled or when the

  - `readiness.py` — truthful probes for `diagnostics-db`, `diagnostics-logs`, `lmstudio`,
    `anythingllm`, `cloud-models`, and `browser`; `not_configured`/`unavailable`/`ok`;
    bounded by `readyz_timeout_seconds`; never raises.
- NEW `ophanim/api/health.py` — `GET /health` (liveness) and `GET /readyz` (200 ready /
  503 when any `OPHANIM_READYZ_REQUIRED_COMPONENTS` component is not `ok`), settings via
  `Annotated` dependency.
- NEW `ophanim/api/metrics.py` — `GET /metrics` in Prometheus text format.

**Architecture impact**:
Adds an `ophanim/observability` layer that sits above the domain. The domain layer
remains framework-free; `ophanim.observability` is added to the forbidden set for
`ophanim/domain` imports (verified by `test_architecture_boundaries` and the
architecture guard). `readiness.py` reuses existing adapters (`LMStudioClient`,
`AnythingLLMClient`, `DatabaseQueryTool`, `build_configured_cloud_providers`) behind
settings-driven probes, so no new adapter surfaces are introduced. The FastAPI routes in
`ophanim/api/` stay thin (delegate to `probe_readiness` / the metrics registry).

**Security impact**:
- Structured logging redacts secret-shaped values (`sk-...`, `api_key=`, etc.) both in
  the JSONL formatter extras and via the message filter; access-log paths are redacted.
- Correlation ids are validated and replaced when malformed (no header injection).
- `/metrics` exposes aggregate counters only (never payloads, bodies, or secrets).
- OTel is off by default; when enabled it ships only metrics/traces with a redacted
  service resource — no secret values are exported.
- Docker artifacts exclude `.env`, logs, pids, caches, and tests; the container runs as a
  non-root user.
- Readiness probes are truthful (`not_configured` vs `unavailable`) and never raise;
  `/readyz` only gates on explicitly required components.

**Acceptance criteria verification**:
1. `GET /health` returns `{"status": "ok", "service": "ophanim-core"}` (existing test
   unchanged).
2. `GET /readyz` returns 200 with truthful per-dependency status when ready and 503 with
   `required_unavailable` when a required component is not `ok`.
3. Structured JSONL logs carry a stable schema (`ts/level/logger/msg/service/environment`
   + correlation id) and redact secret-shaped values in messages and access-log paths.
4. Request metrics (counter by method+status, latency histogram) are recorded by the
   middleware and rendered by `GET /metrics` in Prometheus text format.
5. `X-Correlation-ID` is honored (valid UUID) and echoed; missing/invalid ids are
   generated/replaced.
6. OTel degrades to a no-op when disabled or when the SDK is absent; the enabled path
   initializes providers and produces real spans.
7. Tracker updated; this checkpoint created.

**Migrations/rollback**: N/A — no schema changes. The feature is additive: removing
`ophanim/observability/`, `ophanim/api/health.py`, `ophanim/api/metrics.py`, the
config additions, the `[otel]` extra, the Docker/compose/`.env.example` artifacts, and
the `main.py` wiring rolls back cleanly.

**Known limitations**:
- OTel exporters/collector require the optional `[otel]` extra and a local collector
  (compose profile); telemetry is best-effort when the endpoint is unreachable.
- `grafana/provisioning` ships datasource/dashboard providers only (no curated dashboards
  yet); metrics visibility relies on the default `/metrics` scrape.
- Readiness probes only exercise configured dependencies; unconfigured components report
  `not_configured` truthfully and do not block readiness.
- `diagnostics-db` readiness runs a real `SELECT 1` probe and is bounded by
  `readyz_timeout_seconds`.
