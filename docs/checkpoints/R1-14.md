# Task Checkpoint: R1-14 (Diagnostic DB & Log Tools)

**Task ID**: R1-14
**Status**: COMPLETED
**Completed at**: 2026-08-16

**Objective**:
Deliver deterministic, policy-governed, read-only database query and structured log
search tools with output sanitization, so the Transaction Investigation Skill (R1-15)
can rely on them.

**Scope delivered**:
- `ophanim/diagnostics/redaction.py` — secret-aware redaction (API keys, bearer tokens,
  passwords, secret-labeled values, private-key blocks, `sk-...`/`AIza...` shapes).
- `ophanim/diagnostics/db_query.py` — `DatabaseQueryTool`: parameterized read-only
  SELECT/WITH queries against SQLite opened in read-only mode with `PRAGMA query_only=ON`
  (defense in depth) plus static rejection of write/admin/multi-statement input; bounded
  rows and cell truncation; secret redaction per cell.
- `ophanim/diagnostics/log_search.py` — `LogSearchTool`: structured JSONL search with
  level/source/keyword/correlation-id/time-range filters and recursive secret redaction.
- `ophanim/diagnostics/service.py` — `DiagnosticsService` enforces default-deny policy
  before every tool execution and returns the auditable `PolicyDecision`; explicit
  allowlist rules (`diagnostics_policy_rules`) for the Assistant role.
- `ophanim/api/diagnostics.py` — authenticated `POST /api/v1/diagnostics/db/query` and
  `POST /api/v1/diagnostics/logs/search` with thin handlers (401/403/422/503 mapping).
- Wired into `config.py` (diagnostics DSN/log path/limits), `runtime.py`
  (`RuntimeComposition.diagnostics_service` + policy rules), and `main.py` (router +
  dependency overrides).

**Architecture impact**:
Introduces a policy-governed read-only diagnostics tool surface in the Core control
plane, consistent with the deterministic-tools-execute-side-effects rule. Tools are
typed and Pydantic-validated at the API boundary; the domain layer stays framework-free.

**Security impact**:
- Default-deny: unapproved `diagnostics.*` actions raise `PolicyDeniedError` (API 403).
- Read-only enforcement: SQLite opened read-only (`mode=ro` URI) + `PRAGMA query_only=ON`;
  write/admin/multi-statement SQL rejected statically; parameters always bound.
- Output sanitization: secret-shaped values redacted in query cells and log records;
  rows and cells capped.
- No new secrets are introduced; credentials stay execution-time resolved.

**Known limitations**:
- SQLite dialect only; a PostgreSQL adapter is a future extension point behind the same
  `DatabaseQueryTool` interface.
- Diagnostics sources are unconfigured by default in dev, so the API truthfully returns
  503 until `OPHANIM_DIAGNOSTICS_DB_DSN` / `OPHANIM_DIAGNOSTICS_LOG_PATH` are set.
- Structured JSONL log search expects JSONL; the current dev backend.log (uvicorn
  access/standard logs) is not structured and yields zero matches (R1-16 observability
  will introduce a structured handler).
- Role-based policy rule is the current enforcement; principal-scope tightening is
  reserved for R1-17 hardening.
